# MacInterop adapters — design

Slice: [Port the MacInterop adapters from the probe](https://github.com/DanielMulec/jevpaste/issues/22).
Evidence: `spike/macos-probe` (`RESULTS.md`), [Validate macOS permissions, browser context and paste
preservation](https://github.com/DanielMulec/jevpaste/issues/11), [Establish macOS capture, context, insertion
and secret-detection limits](https://github.com/DanielMulec/jevpaste/issues/3). Ports are fixed by Core
(`docs/design/paste-attempt-state-machine.md`); nothing in Core changes except two `periphery:ignore` comments.

All four adapters are `@MainActor final class`es (Carbon, AX and `NSPasteboard` are main-thread APIs). Pure
decisions sit in small internal value types so they are unit-testable without AX, a grant or a real keystroke.

## Clipboard — `SystemClipboard`
- **Mechanism.** `init(pasteboard: NSPasteboard = .general, pollingSchedule: some PollingSchedule = .timer(100 ms))`.
  `snapshot()` reads every item × every type as `Data` (a type whose data cannot be read is dropped: it cannot be
  restored either). `write(_:)` uses `prepareForNewContents(with: .currentHostOnly)` (the Paste Result never reaches
  Universal Clipboard), writes `.string` plus `org.nspasteboard.TransientType`, `AutoGeneratedType` and
  `org.nspasteboard.source = com.jevpaste.JevPaste` (other clipboard managers skip it; probe wrote exactly this on
  all five Targets). `restore(_:)` clears and writes one `NSPasteboardItem` per snapshot item. Both return
  `pasteboard.changeCount` read after the write.
- **Observation.** `startObservingChanges` polls `changeCount` on each tick of the `PollingSchedule` (default a main
  run-loop `Timer`, 100 ms; `.common` mode). A tick never runs inside `write`/`restore`, so Core always marks its own
  count first. Per change: marker types are checked **before** content is read; `item` = first `.string` found,
  `isConcealed` = any of `org.nspasteboard.ConcealedType`, `.TransientType`, `.AutoGeneratedType`,
  `de.petermaurer.TransientPasteboardType`, `com.typeit4me.clipping`, `Pasteboard generator type`,
  `com.agilebits.onepassword`. Restored contents are reported like any other change.
- **Threading.** Main actor only; the timer fires on the main run loop.
- **Unit-tested** on a private `NSPasteboard(name: .init(UUID))` with a manual `PollingSchedule`: write→snapshot
  round trip, multi-type restore byte for byte, returned count == `changeCount`, no callback until a tick, one
  callback per change with text and count, restored text reported, each marker → `isConcealed`, no text → `item nil`.

## Hotkey — `GlobalHotkey`
- **Mechanism.** Carbon `RegisterEventHotKey(kVK_ANSI_V, cmdKey | shiftKey)` + `InstallEventHandler` on the
  application event target (probe: fires with zero TCC grants, also under secure input). The C callback reaches the
  instance through the `userData` pointer and hops with `MainActor.assumeIsolated` (Carbon calls on the main thread).
  No CGEventTap / `NSEvent` monitor, so no dedup window is needed.
- **Unit-tested:** nothing that registers the shortcut (it would swallow Daniel's ⌘⇧V during `swift test`).
  **Probe-proven:** the press triggers the probe delivery.

## TargetResolver — `AccessibilityTargetResolver`
- **Mechanism.** System-wide `AXFocusedUIElement` (messaging timeout 0.5 s). On `noValue`, one ordinary `AXChildren`
  walk of the frontmost app's focused window (wakes Chromium trees), then one retry. pid = `AXUIElementGetPid`.
  - *Editable:* role `AXTextField`, `AXTextArea`, `AXComboBox`, subrole `AXSecureTextField`/`AXSearchField`, or
    settable `AXSelectedTextRange`. Otherwise `nil` (e.g. a just-launched Catalyst `iOSContentGroup`).
  - *Secure:* subrole or role `AXSecureTextField`, or `IsSecureEventInputEnabled()`.
  - *Identity:* `elementToken` is a counter; the resolver keeps the last bound `(token, AXUIElement)`.
    `isStillFocused` re-resolves focus and is true only if pid matches and `CFEqual(current, bound)`.
- **Target Context.** `fieldLabel` = `AXTitle`, else `AXTitleUIElement`'s value, else `AXDescription`;
  `placeholder` = `AXPlaceholderValue`; `sectionHeading` = first titled/described `AXGroup` ancestor (fieldset legend,
  ≤ 6 levels); `siblingFieldLabels` = labels of other editable children of the parent (≤ 10). `surroundingText`
  always (labelled fields are often underdetermined without it): breadth-first text (`AXValue`/`AXTitle`/
  `AXDescription`, secure fields skipped) of the nearest `AXWebArea` ancestor, else the focused window, capped at 2 000 characters, 600 nodes, 250 ms.
  Terminals (focused `AXTextArea` whose window has no other text node, i.e. Ghostty's window scrape) get the **last**
  2 000 characters of the element's own `AXValue` — nearest the prompt. Cross-pane bleed in Herdr is accepted, per
  the brief. AX does not report visibility; "visible" = what AX exposes.
- **Threading.** Main actor; AX calls are synchronous (probe: 0.3–9 ms lookup, ≤ 68 ms context on Chrome).
- **Unit-tested:** editable/secure classification, context assembly and bounding (head for pages, tail for
  terminals, grapheme-safe, fragment joining), token bookkeeping (unknown/stale token → not focused) — all over plain
  values. **Probe-proven:** real AX resolution, wake retry, `isStillFocused` on Chrome and Ghostty.

## Inserter — `PasteboardSwapInserter` (renamed `PasteKeystrokeInserter`: it no longer swaps)
- **Mechanism.** Two `CGEvent`s from a `.privateState` source, `kVK_ANSI_V` down/up with `.maskCommand`,
  posted to `.cghidEventTap`. Nothing else, ever: no Return, no key sequence, no AX setter.
- **Key-release wait (found by the probe run).** Chrome drops a ⌘V that arrives while ⌘⇧V is still physically
  held; the private source alone did not fix it. `postPasteKeystroke` first polls the HID state of ⌘/⇧/V every
  10 ms, at most 1 s, then posts (probe: 132–207 ms waited per press, then 6/6 inserted). Blocks the main actor.
- **Unit-tested:** the built event pair (key code 9, command flag only, down then up, private source) without
  posting; the wait (none / until release / give up after 100 polls) over a fake keyboard.
  **Probe-proven:** actual paste.

## Probe plan (step 3)
- `JevPasteApp --probe <log-path>`: registers `GlobalHotkey`; each press runs Core's delivery order over the real
  adapters — `resolveFocusedTarget` → `isStillFocused` → `snapshot` → `write("JEVPASTE-PROBE-<n>")` →
  `postPasteKeystroke` → 120 ms → foreign-change guard → `restore` → compare a fresh `snapshot` with the original.
  Logs only: target pid/role, context field lengths, secure flag, counts, `restoredByteForByte`, and (Chrome) whether
  the synthetic marker is in `AXValue` 500 ms later. Never payloads or real field text. Quits after 5 presses / 5 min.
- Signed with `jevpaste-dev` via `make app` into `build/JevPaste.app`, launched with `open -n … --args --probe`,
  so the designated requirement matches the existing grant without installing. If `AXIsProcessTrusted()` is false
  there, ask before `make install`.
- Chrome: `data:text/html,<textarea autofocus></textarea>`; Daniel clicks in, presses ⌘⇧V. Ghostty: a scratch Herdr
  pane running `cat -v` with DECSET 2004 set; I verify with `herdr pane read` (no newline ⇒ nothing sent). Before
  each: I seed the clipboard with a synthetic 3-type original (string, html, custom type) — Daniel's clipboard is
  replaced once (confirm).
